# CursorMochi：架构与实施任务包 v2

编写日期：2026-09-14。

这是 **v0.1 产品的第二版架构任务书**，不是 CursorMochi 2.0，也不是已经实现的软件。
技术方向保持 Rust + GTK4/GIO；优先稳定、兼容、正确性和可维护性，再考虑轻量化。

## 阅读顺序

1. `docs/ARCHITECTURE_V2.md`：边界、数据流与关键行为契约。
2. `docs/IMPLEMENTATION_V2.md`：按依赖顺序实施的任务及交付要求。
3. `docs/ACCEPTANCE_V2.md`：回归样例与验收门槛。
4. `AGENTS.md`：持续适用的工程约束。
5. `CODEX_START.txt`：给 Codex 的启动任务。
6. `docs/SOURCES.md`：技术依据、来源和适用限制。

## 与上一版的关系

在 v0.1 的同一范围内补强：本地主题发现、真实 Xcursor 预览、GNOME 显式应用、单级撤销。
本版修正旧说明中的简化：不能按整套目录简单去重；不能用当前主题的命名光标冒充选中主题；不能把 GSettings 的 revert 当作已提交设置的撤销；不能把目标环境当作已实测环境。

旧任务书的目标仍保留，具体冲突以本任务包为准。已有仓库的适用规则、用户文件与有效实现不得被直接覆盖。将本文档放进已有仓库时，先比较现状再合并；已有 AGENTS.md 需要合并，不能无条件替换。

## 明确未做的事情

此交付只包含设计与任务文件，没有检出用户仓库，没有修改用户电脑，没有构建应用，也没有执行 GNOME/Wayland 兼容性测试。
Ubuntu 26.04 / GNOME 50 / Wayland / x86_64 是用户提供的**目标环境，尚待验证**。

## 不扩大范围

v0.1 不实现 Windows CUR/ANI 导入、ZIP 解压、安装/删除主题、社区商店、网络、账号、后台服务、KDE/XFCE 写入、Flatpak 或 AppImage 打包。
未来扩展点在设计中说明，但不创建空模块、空仓库或完整插件协议。
