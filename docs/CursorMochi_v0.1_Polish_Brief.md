日期：2026-09-14

目标：保持 Rust + GTK4/GIO 与现有四层边界，把第一版检查界面打磨成可理解、可操作的本地光标管理器。

这不是架构 v3，不新增商店、导入、安装、删除或网络功能。

## 2. 阶段 A：先修正候选主题与有效光标主题的区分

### 观察到的代码路径

Repository::scan 目前仅在 roles 和 inherits 同时为空时跳过目录。因此，没有任何 cursor 文件、但 index.theme 含有 Inherits 的普通图标主题也能进入列表。

Repository::preview 在指定主题找不到角色时，会尝试 default。自动回退可用于缺失角色的预览，却不能作为“候选主题本身有效”的证明。

截图中的 Colloid 条目只是核查线索，不可仅凭名称认定它们全部无效，也不可硬编码名称黑名单。

### 所需行为

区分“发现候选目录”和“判定可用光标来源”。至少区分：

- 有直接光标数据的主题；
- 沿显式 Inherits 关系可以取得实际光标的继承型主题；
- 没有有效光标来源、只是最终自动回退到 default 的候选；
- 内容损坏、无法读取、验证尚未完成的候选。

可用主列表中的主题须有实际直接来源或明确的继承来源证据。不能只检查有没有 index.theme、Inherits 或随意命名的文件。

不能简单禁止所有没有 cursors/ 的目录：合法的继承型主题和 default 入口可能没有自己的图片。

默认兜底不能证明一个目录是独立光标主题。仅有部分角色的主题不必全部剔除；正确标注其缺失、继承、回退情况。难以确定作者意图时展示来源，不伪造“独立主题”结论。

先用最小 fixture 复现，再修复。探测须有界、可取消，使用现有读取和解码预算，不在 GTK 主线程扫描整套二进制。

### 回归用例

1. 只有图标、Inherits=hicolor、无任何可达 cursor：不作为已验证可用光标主题显示。
2. 无本地 cursor、显式继承有效父主题：保留，并标记继承。
3. 缺失父主题、继承循环、损坏 cursor：有诊断，不崩溃。
4. 只有自动 default 回退成功：不能冒充候选本身有效。
5. 同名多目录逐角色解析、合法链接和系统 default 入口：不退化。
6. 有部分有效角色的主题：允许检查，缺失与回退准确展示。

## 3. 阶段 B：保留双栏，重排信息层级

不要先做全窗口毛玻璃、背景动效或更换 GUI 框架。保持当前英文界面。先完成结构和交互，再做少量视觉统一。

### 左栏：主题浏览

- 保留搜索与键盘导航。
- 每行提供静态真实缩略图、主题名和必要状态；当前配置匹配项显示 In use，选中项用选择态，二者不可混同。
- 缩略图使用真实主题来源；继承/回退不得伪装成原创主题图。
- 只加载可见或邻近条目的缩略图，限制队列与缓存，不让所有主题同时播放动画。
- 长名称省略并可查看完整名称；同展示名用 ID/来源消歧，不把相近名字直接合并。
- 启动时优先定位当前配置主题；不存在时明确提示，不修改配置来配合列表。
- 刷新尽量保留搜索词和仍然存在的选择；重新对新列表应用过滤。原选择消失时清晰处理，不留下旧预览。
- 无搜索结果、空目录、加载中和读取失败有对应状态。
- 不重新引入文字抢占点击、导致整行不可选的问题。

### 右栏：以光标为主体

- 顶部突出选中主题名，辅以已安装/继承来源等必要信息。
- 主预览不再默认由大面积深色棋盘占据注意力。提供浅色、深色、低对比透明棋盘背景切换，保证黑白光标可见。
- 清楚区分 1× 逻辑尺寸与检查放大。可提供约 3× 的明确标注检查视图，但不得把放大后的图称为真实桌面物理尺寸。
- 检查放大不得改变 GNOME cursor-size；文件标称尺寸、实际帧尺寸、显示放大仍保持独立。
- Hotspot 默认关闭；在检查选项中开启。缺失/回退/损坏信息不可因美化而隐藏。
- 常用角色使用 Normal、Link、Text、Busy、Resize 等易懂名称；具体文件名和别名放到高级详情或 tooltip。
- 角色集合来自实际可解析数据和明确映射，不用当前系统的命名 cursor 代替选中主题。
- 可增加一行少量常用角色缩略预览，复用缓存和有界任务；不为整个目录生成无限纹理。
- 已有动画功能保持。单帧角色不展示无意义的播放按钮；多帧可提供暂停/播放。
- 第一帧静态卡片仅在有比较价值时保留；单帧角色避免重复显示同一张图。

### 高级详情与诊断

将原始路径、继承链、文件角色名、标称/实际尺寸、原始帧延迟、帧编号等放入可展开的 Technical details。

Copy diagnostics 放到菜单/诊断入口，而不是与主要操作同等突出。保留本地剪贴板和脱敏行为，不增加遥测。

正常状态简洁；只读、写入失败、部分写入、外部冲突、来源无法验证等会影响操作决策的状态仍须显著可见。不要把所有告警一股脑折叠掉。

### 底部操作区

操作区明确关联右栏选中主题，例如 Apply Adwaita，而不是只有含义模糊的 Apply。

GNOME 大小调整保持显式 opt-in。可展示当前大小和拟修改大小，但不要把预览缩放当成设置值。

- 无有效候选/加载失败/只读/忙碌：禁用应用，并能解释原因。
- 配置无变化：清楚显示 Already in use 或 no-op 状态；不要重复制造撤销记录。
- 写入期间提供进度反馈，复用现有串行与回读逻辑。
- 撤销仍是本会话上一次成功修改；尽可能显示将恢复的主题。
- 外部修改发生后不自动覆盖；失败、部分成功和不确定状态仍如实报告。
- “当前配置主题”不等于“已证明所有应用的真实指针都已更新”。文案维持这个边界。

## 4. 小范围代码整理，不重构全项目

可在 cursormochi-gtk 内把界面构建、主题列表、预览组件、动作状态和 smoke 测试辅助拆成几个文件。

保持 core/app/platform/gtk 依赖方向；不新增通用插件系统、事件总线、服务层套娃或额外异步运行时。

当前 main.rs 有约每16 ms回调，且约每250 ms读取设置。它是可测量的后续优化候选，不是已证实的性能瓶颈。不要因为看见定时器就先重写调度。

若本轮调整预览调度，应保证：静态内容没有无意义连续重绘；动画按实际帧时序推进；不可见预览停止不必要工作；设置验证有独立、明确的完成/超时机制；旧请求不能覆盖新选择。记录测量环境与实际数据，不编造节省比例。

## 5. 验证要求

沿用并扩充 scripts/check.sh；至少执行现有工程约定中的 fmt、Clippy、workspace tests、locked release build。可用时执行参考 libXcursor 对照。

自动测试/隔离 GUI 须覆盖：

- 阶段 A 的候选分类与继承/回退用例。
- 当前配置与选中候选各自独立；仅预览不写入。
- 刷新后搜索仍生效、选择保持或正确失效。
- A→B→C 快速选择、坏主题插入、后台过期结果。
- 单帧与多帧、预览缩放与 GNOME 大小不混淆。
- 技术详情展开、诊断可访问、关键告警不被折叠隐藏。
- 列表行点击、键盘焦点、禁用按钮解释。
- 浅色、深色、高对比、不同窗口尺寸；缩放值记录真实观测，不以环境变量代替实际结果。

测试继续显式注入 fake/memory settings backend，不能修改用户真实 dconf。

真实 GNOME Apply/Undo、浏览器/GTK/Qt 窗口表现、100%/200%/分数缩放、外部修改冲突，由用户明确发起验收。没有执行即写 NOT RUN，不擅自点击真实 Apply。

## 7. 验收目标

第一次打开程序的人，应该能很快看懂：

1. 当前配置是哪套主题；
2. 现在浏览的是哪套、它实际长什么样；
3. 点击应用会改变什么，发生问题后如何撤销。

技术深度保留在可访问的详情里，不要求用户先理解 Xcursor 文件格式才能换鼠标。
